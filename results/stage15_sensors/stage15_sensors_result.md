# 1.5단계 결과 — 온도 센서 배치와 전체 지도 복원 (2026-11-15)

조건: 온도까지 고려한 최종 배치(가중치 1.0, 시드 0), 블록 전력 ×U(0.2, 1.5) 무작위 상황 500개(학습 400 / 시험 100),
시험 상황 최고 온도 평균 57.2°C(범위 47.2~63.7°C). **모든 값은 가정 기반 시뮬레이션.**

## 핵심 숫자 (센서 오차 없음, 시험 100개 평균)

| 센서 개수 | 격자 + 가까운 값 (RMSE / 최고온도 오차) | 뜨거운 블록 위 + 가까운 값 | 데이터 기반 + 패턴 복원 |
|---|---|---|---|
| 2 | 5.23 / 5.22 °C | 7.27 / 3.39 | **2.60 / 1.21** |
| 4 | 4.25 / 3.62 | 7.11 / **0.11** | **2.16** / 1.01 |
| 8 | 3.12 / 3.00 | 6.12 / **0.10** | **1.20 / 0.15** |
| 16 | 1.89 / 5.72 | 2.87 / 0.10 | **0.49 / 0.04** |

## 알게 된 것
1. **데이터 기반 배치 + 패턴 복원이 칩 전체 지도는 가장 잘 맞힘.** 센서 8개로 RMSE 1.2°C, 16개로 0.49°C.
2. **뜨거운 블록 위에 센서를 두면 최고 온도는 잘 잡지만(오차 약 0.1°C), 나머지 지도는 거의 못 맞힘(RMSE 6~7°C).**
   단, 어떤 블록이 뜨거운지 미리 안다는 가정이 들어 있음 (이 실험은 뜨거운 블록이 계속 뜨거운 설정).
3. **위치가 나쁘면 똑똑한 복원법이 오히려 망가짐.** 격자 배치 16개 + 패턴 복원은 RMSE 86°C, 센서 오차 ±1°C면 217°C.
   이유는 '조건수'(센서 오차가 결과로 얼마나 커지나): 격자 16개는 1,580, 데이터 기반은 2.4.
   → 캡스톤 오차 분석(비율 1% 오차가 온도 오차를 크게 키움, 시뮬레이션)과 같은 원리: **측정 오차는 계산 구조에 따라 증폭된다.**
4. 센서 오차 ±1°C를 넣어도 데이터 기반은 16개에서 RMSE 0.49 → 0.67°C로 버팀.
5. 데이터 기반 배치는 센서를 칩 모서리·가장자리에도 둠 (사람 직관과 다름) — 프린스턴 논문의 "사람이 생각 못 한 배치"와 비슷한 장면.

## 한계
- 동작 상황이 블록별 무작위 배수라 실제 작업 부하 패턴과 다름
- 센서 오차는 균등분포 가정, 센서 위치는 격자 칸 중앙으로 근사
- 학습과 시험이 같은 배치·같은 발열 분포에서 나옴 → 새 칩 배치로 일반화되는지는 확인 안 함
- 데이터 기반 방법은 주성분 분석 + QR 선택(EigenMaps와 같은 계열), 신경망은 아직 아님 (2단계)
