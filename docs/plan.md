# 프로젝트 계획서: 열을 고려한 칩 배치

| 항목 | 내용 |
|---|---|
| 작성일 | 2026-11-15 (최종 갱신 2026-11-16) |
| 형태 | 개인 탐색 프로젝트 |
| 환경 | 개인 노트북, Python, CPU only |

---

## 1. 목적
칩 설계 단계에서 열을 빠르게 예측하려는 업계 흐름(연구: ThermEDGe, DeepOHeat / 상용: Cadence Celsius Studio)을 작은 규모로 직접 구현하여, 열을 고려한 배치와 센서 기반 온도 추정이 실제로 어떤 효과를 내는지 확인한다. 신경망의 우위를 전제로 두지 않고, 기존 방법과 같은 조건에서 비교한다.

## 2. 배경

**현재의 문제**
- 블록 배치는 위치를 수만 번 바꿔 보며 좋은 배치를 찾는 탐색이지만, 정확한 열 해석은 비용이 커서 매 단계 수행하기 어렵다.
- 그 결과 배치 중에는 전력 밀도 정도만 보고, 정확한 온도는 배치 후에 확인한다. 핫스팟이 발견되면 배치를 다시 해야 한다.
- 칩은 동작 상황마다 발열 위치가 달라지며, 온도 센서는 소수만 배치되므로 센서가 없는 곳의 핫스팟을 놓칠 수 있다.

**빠른 열 예측이 가능해지면**
- 배치를 바꿀 때마다 온도를 확인할 수 있다.
- 여러 동작 상황을 동시에 고려한 배치가 가능하다.
- 소수의 센서 값으로 칩 전체 온도 지도를 복원할 수 있다.

**선행 사례**: 설계 대리모델로 탐색 시간을 줄인 사례로 Karahan et al. (*Nature Communications*, 2024)이 있다(학습 데이터 생성 약 13일 → 이후 설계 1건 약 6분). 상세 조사는 [`data_check.md`](data_check.md).

## 3. 문제 정의
정해진 칩 면적 안에 블록을 배치할 때 **(1) 블록 간 배선 길이와 (2) 칩 최고 온도를 함께 줄이는 배치**를 찾고, **소수의 온도 센서로 칩 전체 온도를 얼마나 정확히 알 수 있는지** 확인한다.

- 두 목표는 상충한다. 고발열 블록을 가까이 두면 배선은 짧아지지만 온도가 오른다.
- 회로 수준이 아니라 블록의 크기·전력·연결 관계만 다룬다.

## 4. 단계 구성

| 단계 | 내용 | 비교 기준 | 상태 |
|---|---|---|---|
| 0 | 2D 정상상태 열 해석기 구현·검증 | 해석해·손계산 (허용 오차 1%) | 완료 |
| 1 | 열을 고려한 블록 배치 | 배선만 고려한 시뮬레이티드 어닐링 | 완료 |
| 1.5 | 온도 센서 배치와 온도 지도 복원 | 격자 배치, 최근접 보간 | 완료 |
| 2 | 센서 복원 신경망 (처음 보는 배치로 일반화) | 최근접 보간, 패턴 복원 | 완료 |
| 부가 | 광학 스테이지 열 변형 → 정렬 오차 | 손계산 | 완료 |
| 3 | 패키지 확장: 구리 패턴에 의한 핫스팟 완화, 리플로 휨 | — | 미착수 |

## 5. 범위

**포함**
- 데이터: MCNC ami33 (블록·연결 정보). 블록 전력값은 가정으로 정하고 명시
- 단층 2D 칩
- 직접 구현한 열 해석기로 데이터 생성

**제외**
- 실제 회로 넷리스트, 트랜지스터 수준 해석
- 3D 적층 칩
- 실제 칩 제작·실측, 상용 도구

## 6. 성공 기준
1. 열 해석기가 해석해·손계산과 1% 이내로 일치한다.
2. 배선만 고려한 배치와 열까지 고려한 배치를 같은 조건(같은 시드)에서 비교한다.
3. 센서 개수·배치에 따른 복원 정확도를 정량화한다.
4. 신경망은 기존 방법과 같은 데이터·같은 센서 조건에서 비교하고, 지는 경우도 그대로 보고한다.
5. 각 결과에 한계를 명시한다.
